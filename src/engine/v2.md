# Native v2 graph events

Compiled LangGraph graphs that expose `streamEvents` run once through LangGraph's `version: "v3"` event API. The runtime stores each native `ProtocolEvent` under the run and keeps root `updates` and `values` in the legacy event log. `runtime.supportsV2(graphId)` identifies graphs with this capability.

`runtime.streamV2(runId, { after, pollMs, signal })` replays stored native events and follows the active run. It yields `{ id, event }`. `event` is LangGraph's envelope with `type`, `seq`, `method`, and `params` including `namespace`, optional `node`, and `data`. The `id` is the database cursor for that run, so use it as the next `after` value. Native `seq` starts at zero for each graph invocation and is separate from the database cursor. The API layer owns thread-wide subscriptions, channel filters, and command acknowledgements.

The native stream carries `messages` content-block events from streaming chat models, `tools` lifecycle events from LangChain tools, and child namespaces from compiled subgraphs. A node that directly returns an `AIMessage` contributes to `values` and `updates`; it does not emit token deltas because no model stream occurred. Custom deterministic graph definitions and compiled-like objects without `streamEvents` continue through the legacy stream path and do not produce native v2 envelopes.

On a checkpointed interrupt, the runtime emits `input.requested` with the persisted interrupt ID and reports root lifecycle `interrupted`. LangGraph's raw v3 stream currently reports root `completed` for this case, so the runtime corrects the terminal event using the saved state.

The database cursor avoids replaying rows already read on reconnection. Graph work can run again after a process crash, so consumers should still tolerate repeated semantic events. The runtime does not yet prune old event rows automatically.
